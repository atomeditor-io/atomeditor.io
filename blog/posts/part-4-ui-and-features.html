UI & feature refresh — keep the soul, modernize the chrome

2026-09-13 · Part 4 of the chase log

The core editor climbs Electron fine now. The next stretch is the surface: which bundled packages actually crash on modern Chromium, which ones deserve a deliberate bump, and how the interface should feel in 2026.

Debug first

An audit of the 90+ bundled packages ranks the real user-visible breakages:

  1. github — the renderer 404s when its web worker loads over file:// under modern Chromium; candidate fix is a custom protocol / allowFileAccess.
  2. tree-sitter — null-node type errors on some files; grammars get non-fatal fallback to the tokenizer, then per-grammar fixes.
  3. autocomplete-* — legacy requestAnimationFrame / TextBuffer API drift.
  4. spell-check — hunspell path and dictionary fetching.

Update deliberately, not wholesale

Bumping every pin at once invites API churn across core. The rule is one package per release rung, gated by the test-install + smoke gate, security fixes first, and commit-pinned dependencies kept reproducible — never floating branches.

Where Pulsar already modernized a package, we adopt their port when licensing matches (MIT).

Curated additions

Not everything worth having is bundled. Candidates, opt-out capable, each with a smoke entry:

  • Editor: minimap, highlight-selected, tab-numbers, project-manager.
  • Tooling: linter + linter-ui-default behind an “enhanced tooling” opt-in; atom-typescript.
  • Git: git-grep, merge-conflicts, git-log.
  • Markdown: markdown-preview-enhanced.
  • Quality-of-life: file-icons, relative-numbers, script.
  • Themes: a community-theme pack (dracula, material, nord, gruvbox) as optional download; default stays one-dark.

UI refresh

The redesign philosophy is explicit: don't try to be VS Code — compete on philosophy. Keep the hackable soul, refresh the chrome.

  • Tab bar — rounded tabs, accent underline for the active one, always-visible close buttons.
  • Tree view — collapsed sections, tighter nesting, sticky project header, optional file-type icons.
  • Command palette — grouped results, recent-first, keybinding hints.
  • Settings — card layout, search-first, live theme preview, JSON import/export.
  • Accessibility — ARIA on custom elements, high-contrast mode, 44px touch targets, color-blind-safe theme.
  • Theme compatibility — new styles behind CSS variables; legacy themes keep working, changes are opt-in.

Phase 1 is the low-hanging fruit (tab bar, status-bar actions, focus rings); the tree view and find/replace land next. Everything rides the same per-rung release cadence — gated, greened, shipped.
